## Scope

V1.2.0 changes how existing state and controls are presented. It does not add a
feature, a preference key, a storage format, a permission flow, or a security
decision.

The release has three visible goals:

1. Replace the long Settings page with a compact category hub and dedicated
   detail pages.
2. Reduce Home to a calmer protection overview.
3. Keep the floating navigation pill but make it visually quieter.

## Settings category hub

`SettingsScreen.kt` is now a landing page only. It lists nine categories with a
title, a one-line summary, an icon, and a chevron. It contains no switches,
timeout chips, diagnostics, permission actions, or vault controls.

| Category | Dedicated page contents |
| --- | --- |
| Protection | Protection monitor switch, privacy cover switch, protected-app count and app picker |
| Authentication & Recovery | Volume-pattern and biometric factor status and setup/change, main PIN status and change, protection decoy switch, decoy visibility and stage-window chips, recovery PIN and recovery pattern |
| Vaults | Personal Vault and Intruder Vault status/open actions, Intruder capture readiness and capture control |
| Notifications | Android notification permission state, open-settings action, and the existing explanation of how notifications are used |
| Appearance | Always-dark management-interface status and the existing compatibility note about the retained legacy theme value |
| Permissions | Overlay, Accessibility detection, Usage access fallback, restricted-settings guidance, notifications, and battery optimization |
| Security & Monitoring | Monitor/detection/service status, journal count, security-journal access, and the existing protection explanation |
| Battery & Background Operation | Battery-optimization state, open-settings action, and background-limit guidance |
| About NEXO LOCK | The existing About screen with version, features, security model, and limits |

The category model is `SettingsCategory.kt`. One parameterized route,
`settings/{category}`, renders the eight category pages through
`SettingsCategoryScreen.kt`. About uses the existing `AboutScreen` route.

All detail pages keep the existing back arrow and Android back handling. The
floating pill is hidden on detail pages, as it already was for other subpages, so
a security or permission flow cannot be abandoned with a stray tab tap.

## Home dashboard

`DashboardScreen.kt` now contains only:

- a compact `NEXO LOCK / PROTECTION` header with the Settings action;
- one primary protection card with the master switch, real status pill, one
  explanatory line, and up to three accurate stats;
- at most one actionable warning, selected by a fixed priority;
- three shortcuts: App Lock, Personal Vault, Intruder Vault;
- an optional compact recent-activity preview when journal entries exist.

Warning priority:

1. journal write failure;
2. journal integrity failure or corrupted records;
3. Personal Vault index corruption;
4. Intruder Vault index corruption;
5. missing main PIN;
6. protection enabled but monitor stopped;
7. missing overlay access;
8. no active detector;
9. other protection-health warnings;
10. missing volume pattern.

The warning action routes to the existing page that can resolve it. No warning is
duplicated on the Settings hub.

Stats are derived from existing state and are omitted when not meaningful. With a
fresh profile the only stat is `0 Protected apps`; vault and journal stats appear
only after those features are configured or used.

## Navigation

`NexoApp.kt` keeps the same five top-level destinations:

- Home;
- App Lock;
- Personal Vault;
- Intruder Vault;
- Settings.

The new category route is additive. The Settings gear on Home opens the hub. The
hub's About row opens the existing About route. Home callbacks for the warning and
shortcuts use existing destinations.

`SignatureComponents.kt` lowers the floating pill's shadow, darkens its surface,
softens the selected background and tint, and reduces the icon and selected
indicator size. The pill remains the same five-item control.

  stage timing;

## Design decisions

- Reused the existing Signature theme, cards, pills, metrics, icons, and
  typography.
- Reused `NexoUiState`, `NexoViewModel` callbacks, and existing routes.
- Moved controls instead of creating duplicate state or a second settings store.
- Kept the About content on its existing screen rather than duplicating it inside
  a category component.
- Used one parameterized category route instead of nine near-identical routes.
- Kept permission labels and actions tied to the real Android state already
  exposed by the ViewModel.

## Runtime evidence

The V1.2.0 RELEASE APK was installed on a headless API 37 (Android 17) x86_64
emulator over the previous same-key release. It launched successfully and
preserved the existing setup data and journal. First-run setup had already been
completed with volume pattern `UP, UP, DOWN, DOWN` and a six-digit master PIN.
The following were opened and captured:

- Home;
- Settings hub;
- Protection;
- Authentication & Recovery (top and bottom);
- Vaults;
- Notifications;
- Appearance;
- Permissions (top and bottom);
- Security & Monitoring;
- Battery & Background Operation;
- About NEXO LOCK.

The Home warning opened the Permissions category, the floating pill switched
tabs, back navigation returned from detail pages, and the Personal Vault shortcut
opened the secure vault route. See
[V1.2.0_SCREENSHOTS.md](V1.2.0_SCREENSHOTS.md) and
[V1.2.0_TEST_REPORT.md](V1.2.0_TEST_REPORT.md).

## Limitations

- The release remains debug-key signed and is not store-ready.
- Android Lint and instrumented tests were not run.
- Full unlock, lockout, decoy timing, vault import/export, camera capture,
  protected-app overlay coverage, and physical-device upgrade migration were not
  exercised.
- Only one emulator image was used; vendor-specific behaviour and multiple Android
  versions were not tested.
