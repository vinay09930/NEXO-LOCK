## Contents

Build 14 adds Self-Protection and hardens the authorization and vault paths:

- Self-Protection gate for sensitive management changes while App Protection is
  on, reusing the decoy, biometric, volume-pattern, master-PIN, and recovery
  flows.
- Self-Protection is derived from App Protection; there is no separate toggle.
- Step-up grants are bound to the exact pending change. Denied, expired,
  superseded, cancelled, or revoked grants clear the pending change.
- Sensitive writes re-read the persisted requirement and re-check the revocation
  epoch immediately before committing.
- The vault-PIN comparison oracle was removed. Vault PINs are not compared across
  credential families.
- Vault deletion requires an unlocked session and removes ciphertext before the
  credential.
- PIN creation/change guards, atomic index updates, single-shot camera
  completion, and intruder-capture serialization were hardened.
- Image EXIF handling moved to `androidx.exifinterface`.
- Unreachable service actions and unused resources were removed.
- `versionCode` bumped to `14`; `versionName` remains `1.2.0`.

Unchanged:

- package name and application ID;
- signing identity;
- credential verifier format and iteration counts;
- Keystore aliases, AAD domains, vault directories, and `NXLF` v1 container;
- vault index schema and user-data compatibility;
- decoy visuals, text, layout, navigation, and timing.

## Distribution guidance

- Treat this as a **local, build-verified, emulator-smoke-tested release**, not a
  store release.
- Do not publish the APK as a production-signed app.
- Replace the debug signing config with an owner-held keystore before any public
  distribution.
- Run the device acceptance checks on at least one Android 8+ and one Android 14+
  device before relying on protection.
- Keep the APK and checksum file together.

## Known issues

- The release uses the debug signing key.
- The build-14 Self-Protection gate was not driven end to end on a device.
- Full unlock, lockout, decoy timing, vault import/export, camera capture,
  protected-app overlay coverage, and physical-device upgrade migration were not
  exercised.
- Only one API 37 x86_64 emulator image was used.
